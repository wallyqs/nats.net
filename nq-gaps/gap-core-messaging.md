# Feature gap: nats.net Core messaging + peripheral packages vs NQ C# (`csharp.async`)

Scope: publish, serialization, `NatsMsg<T>`, `NatsHeaders`, subscriptions/`NatsSubOpts`, sub events and drain,
request/reply (incl. RequestMany, RequestReplyMode), inbox, `NatsClient` (Simplified), NATS.Net meta package,
OpenTelemetry, DI/Hosting, Abstractions interfaces, zero-copy buffers.

References
- nats.net: `/home/user/nats.net` at `15bd0bf` (v3.3.0 + 1). Paths below are relative to `src/`.
- NQ C#: `/home/user/nq.dev/packages/csharp/src/NQ/` (`NatsConnection.cs`, `NatsSubscription.cs`, `NatsMsg.cs`, `NatsOpts.cs`, `NatsException.cs`); capability record `ir/capabilities/csharp.async.json` (282 symbols: 269 implemented, 13 unsupported, 0 planned).
- Oracle: `/home/user/oracle/nats.go` at `7a8404a` (v1.54.0). Line numbers match the `line` fields of `csharp.async.json` (e.g. `Conn.Publish` 4433, `Header.Add` 4443). The NQ contract inventories only `nats.go`, `context.go`, `nats_iter.go` (`compiler/internal/contract/contract.go:63`), so `enc.go`/`encoders/` are outside it. Secondary oracle: orbit.go `/home/user/oracle/orbit.go` at `8898afe` (`natsext`; NQ's `ir/capabilities/orbit/csharp.async.json` tracks only `jetstreamext` symbols).
- "new since 8bb0fb7": the nats.net change is in `git log 8bb0fb7..HEAD`. That range has 144 commits and covers all of 3.0.0-preview.1 through 3.3.0.

Overall: NQ C# is a byte[]/string, non-generic client modelled on nats.go's API. It uses nats.net's async shape: `ValueTask`, `IAsyncEnumerable`, immutable `NatsOpts` record, `NatsEventHandler` events. It ships as one package, `NQ.Nats` (`NQ.csproj`), whose only dependency is `System.IO.Pipelines`. NQ has no generics, serializer registry, interfaces, OTel, logging, DI or hosting. A grep of the shell files (`NatsConnection.cs NatsSubscription.cs NatsMsg.cs NatsOpts.cs`) finds 0 matches for each of: `Serializ`, `Activity`, `Telemetry`, `Meter`, `ILogger`, `IBufferWriter`, `MemoryOwner`, `RequestMany`, `IdleTimeout`, `StartUpTimeout`, `MaxMsgs`, `OnSubscribed`, `RequestReplyMode`, `WaitUntilSent`, `CaseSensitive`, `DrainSubscriptionsOnDispose`, `EndReason`.

Class legend: **oracle-backed** = a nats.go (or orbit.go) equivalent exists, so NQ can implement it with oracle evidence. **nats.net-only** = no Go equivalent, so nats.net or nats-server must be the reference. **idiom** = .NET API idiom (DI, generics, serializers, OTel, interfaces) rather than protocol behavior. **proto** = affects wire or protocol-visible behavior.

## Prioritized significant gaps

1. **Typed serialization stack (rows 2, 5–9, 10, 12, 14, 29).** NQ has no `INatsSerialize<T>`/`INatsDeserialize<T>`/registry, no generic `NatsMsg<T>`, no `PublishAsync<T>`/`SubscribeAsync<T>`/`RequestAsync<TReq,TRes>`, and no JSON (incl. source-gen and #1253 writer options). This is the largest API-shape gap against nats.net. The only Go analogue is the deprecated EncodedConn (enc.go:31-301, encoders/builtin), which is outside the NQ contract, so nats.net is the reference. It is a .NET idiom, not protocol, and could live entirely in the shell over `byte[]`.
2. **RequestMany (rows 23, 31).** It is missing, and it is oracle-backed through orbit.go `natsext.RequestMany` with Stall, MaxMessages, Sentinel and DefaultSentinel (natsext/requestmany.go:37-101). No NQ capability record tracks natsext, so it is a clean candidate for compiled IR plus oracle evidence. It touches the protocol (sentinel or stall termination of a mux reply stream).
3. **Subscription option surface (rows 21–25, 28).** `NatsSubOpts` is missing entirely: MaxMsgs at subscribe time, Timeout/IdleTimeout/StartUpTimeout, StopOnEmptyMsg, ThrowIfNoResponders toggle, ChannelOpts FullMode (Wait/DropOldest), Events.OnSubscribed. MaxMsgs and capacity map to oracle-backed `AutoUnsubscribe`/`SetPendingLimits`. The lifetime timers, FullMode and OnSubscribed (#1217, new) are nats.net-only.
4. **No-responders behavior on plain subscriptions (rows 13, 24).** NQ's `ReadAllAsync` turns a 503 into a thrown `NatsNoRespondersException`, following nats.go:5791. nats.net delivers it as a message with `HasNoResponders`. This is a protocol-visible behavioral difference that needs a recorded decision: keep the nats.go behavior or add the nats.net-style opt-in.
5. **OpenTelemetry (rows 43–46).** Tracing, metrics, baggage, span formatter and the OTel package are all missing and nats.net-only. Most of it is new since 8bb0fb7 (#1154, #1172, #1194, #1201, #1208, #1229, #1236). Tracing is wire-visible because it injects `traceparent`/baggage headers. Any implementation would need a deterministic seam: no ambient `Activity.Current` inside compiled decisions.
6. **Interfaces, DI, Hosting, Simplified (rows 38–41, 48–50).** No `INatsClient`/`INatsConnection`, `AddNatsClient`/`NatsBuilder`, `AddNats`, `NatsClient` facade or connection pool. All nats.net-only .NET idioms. The interfaces matter most, because DI and mocking build on them.
7. **Drain on dispose / drain options (row 27, #1177 new).** `NatsSubscription.DrainAsync` exists and is oracle-backed. `DrainSubscriptionsOnDispose`, `DrainPingTimeout` and a ct on drain are nats.net-only.
8. **RequestReplyMode (row 32, #1182 new).** NQ's single nats.go mux plus `UseOldRequestStyle` covers the behavior on the wire. The missing piece is the API toggle. Low priority.
9. **Zero-copy (row 51) and per-publish options (row 3).** These are performance and ergonomics idioms (NatsMemoryOwner, ReadOnlySequence publish, WaitUntilSent, PublishTimeoutOnDisconnected). nats.net-only.
10. **Header details (rows 15–18).** Missing: the case-insensitive default and toggle (#1258, new), `Code`/`Messages` enum, `TryGetLastValue`, Header/SubjectEncoding. Small, nats.net-only.

Side finding (not a nats.net gap): `ir/headers.nqir:163,167` annotate header-key validation as `nq:` "nats.go writes keys unchecked". The pinned oracle (nats.go v1.54.0) validates keys in `Msg.headerBytes`, returning `ErrBadHeaderMsg` (nats.go:884-887, `isHeaderKeyValid` :993), and sanitizes CR/LF in values (nats.go:997-1010). NQ throws its own `nats: invalid header key/value` texts. The oracle annotation looks stale against the pinned commit; whether it should be re-adjudicated and recorded in deferred/divergence docs is worth checking.
